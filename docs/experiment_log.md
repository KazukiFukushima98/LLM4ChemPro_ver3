## run24（2026-07-10 18:01 〜 07-11 06:25、9反復・約12.4h 無人）— ver3 初回・feasible 達成

**条件**：ver3 フル設定の初運転。目的 `minimize_cost`（Lee 2018 経済定数・HX 省略・
CAPEX=C·|WNET|）、Robeson 膜モデル（段別独立 permeance、500–6000 GPU）、Lee 整合 bounds
（面積 [1e5,1.5e6] m²・p_perm [0.1,0.99]・COMP [1,4] bar）、feed 80,307 kmol/h（=500 Nm³/s・
CO₂ 15mol%）、自動中間冷却、目標 purity ≥0.95 / recovery ≥0.90、BO 24/60/4・patience 10。

**結果**：SST が seed（2段直列）から **5膜カスケード＋リサイクルを自律発見し両制約を達成**。
- 最良（iter_008）：purity **0.998** / recovery **0.9014** / **73.66 $/tCO2**（532 kWh/tCO2）
- 構造：2段濃縮 + MEMB3（MEMB1残渣の回収段・透過→V1）+ MEMB5（MEMB3残渣の直列2段目
  回収・これが 0.90 の壁を越えた）+ MEMB4（製品精製段・残渣→V4）+ V6リサイクル。最終 0 バイナリ
  （恒常 ON 段を順次 promote）。
- 軌跡（SHORT→cost）：0.424 → 0.248 → 0.161 → 0.060 → 0.205（iter_005 退行→ロールバック）
  → 0.228 → 0.040 → **0（feasible）** → 0.005。

**停止理由**：固定5段構造のコスト最適点が recovery=0.90 制約の真上にあり、同一構造で BO の
シードノイズが制約線をまたぐ（iter_008: 0.9014 ⇄ iter_009: 0.895）。構造の自由度ではなく
内側最適化器の分散が残課題と診断し、probe せず停止（playbook 準拠）。

**教訓・課題**（詳細は run24/HANDOFF.md）：
1. アクティブ制約近傍の BO 分散（回収 ±0.005〜0.15）が改善信号を不安定化。バイナリ8本
   （256トポロジー）で必須段が落ちて退行（iter_005）→ 恒常 ON 段の promote で空間を絞ると
   回復。→ 高バイナリ時の BO 予算増 or 制約近傍の feasibility 重み付け獲得関数を検討。
2. 純度が過剰達成（0.998 vs 0.95）＝コスト余地あり。
3. コストは真空ポンプ支配（VP 計 ~254 MW、リサイクル3本が全て V1 に戻る 2.2 倍負荷）。
   **未着手の最大レバー＝feed 昇圧アーキテクチャ**（Lee の最適域 2.4–3.5 bar）。リサイクル毎の
   再昇圧 COMP が必要な大規模変更のため、次 run の seed/指示として人間が設計判断する。
4. 運用実測：1反復 20分〜4.1h（バイナリ数とほぼ相関）。SST（LLM）の思考は反復あたり数分で、
   計算時間は Aspen 支配。スキーマミス1回（"changes" キー）は自己修正—— apply_ss に
   空適用ガードを追加済み（`f5c1ff3`）。ロールバック機構・再適用 --force も実戦で機能。

**参照値との関係**：73.66 $/t は Lee の 36.3〜42.5 $/t より高いが、既知の系統差
（膜モジュールが Lee の向流モデルより保守的＝同仕様に多面積、feed 昇圧未使用）と整合。

## run25（2026-07-14〜15）— 昇圧空間での SST・52.12 $/tCO2（run24 比 −29%）

**セットアップ**：昇圧 campaign やり直しの第1走（`f2424a1`）。seed に固定 COMP1
（feed 1 bar → V9 合流点 → COMP1 → MEMB1、pout ∈ [1.1, 4.0] の連続変数）を導入した
2膜直列から開始。他条件は run24 と同一（Lee スケール・目標 0.95/0.90・BO 24/60/4・
patience 10・minimize_cost）。Mixer 規則(4)（素通し給餌のユニット入口を Mixer 化）を
同コミットで追加——導入時の実機 smoke で pre-mixer 配置が全評価 silent BAD になる
builder の穴を発見・修正したもの。

**結果**：**best = iter_004: 52.12 $/tCO2**（purity 0.972 / recovery 0.903 / 542 kWh/t / 260 MW）。
- 構造：COMP1(4.0 bar) + 3膜（MEMB3 は V3 残渣の回収段）+ V6→V9 全量リサイクル。
- 軌跡（7反復・943評価）：未達0.283 → **feasible 107.28** → 未達0.019 → **52.12 ★**
  → 未達0.020 → 68.55 → 52.82。未達3回はいずれも「MEMB3 OFF の2膜構成」盆地に
  BO が吸われて回収88%の壁で patience 切れ＝promote による空間縮小（バイナリ 5→3→2）で解消。
- **run24（真空のみ）73.66 → 52.12（−29%）**。昇圧の解禁が主効果で、feed 昇圧は
  全 feasible best で上限 4 bar に張り付き。

**確定知見**：(1) 3段目回収段は feasibility の必要条件（feasible/未達と MEMB3 ON/OFF が完全対応）。
(2) V6→V9 全量リサイクルは全 best で恒常 ON（組成マッチの V6→V4 は一度も選ばれず）。
(3) EXP（4 bar 残渣の膨張回収）は動作するがコスト最適でない（劣位盆地でのみ採用、
52 盆地では bypass＝CAPEX 500 $/kW が回収益超過）。(4) 役割分担膜（1段目高透過・
2段目高選択）を BO が自力再発見（Lee Fig.5b と同結論）。

**停止理由**：iter_005〜007 の3反復連続で best 未更新（収束）。詳細は run25/HANDOFF.md。

**次**：同じ昇圧空間で baseline（ss_lee2/ss_lee3 の一括最適化、各段固定 COMP 入り）を
回して SST と比較（12.6 本命）。Lee 絶対値（36〜42 $/t）との残差分は
膜流動様式（向流 vs GasPermModule）が支配、他は保守側簡略化（リサイクル膨張回収なし）
と楽観側（HX コスト省略 ~2%）。

## run26（2026-07-15）— ブロワーシナリオの SST・61.29 $/tCO2（4膜、run24 比 −17%）

**セットアップ**：全膜入口 1.1 bar 統一・COMP 種別ごと固定（GA/BO 変数から完全除外、
`6dc66c7`）の Merkel/MTR 型 blower+vacuum シナリオ。目標・経済・BO 設定は run24/25 と同一
（95%/90%・minimize_cost・BO 24/60/4・patience 10）。**完全ブラインドの別セッション**
（/sst-loop）が実行——run25 の記憶を持つ開発セッションは提案に関与せず、監視・検収のみ。

**結果**：**best = iter_006: 61.29 $/tCO2**（purity 95.4% / recovery 90.8% / 466 kWh/t /
総動力 224 MW）。9反復・計1,530評価で収束停止（コスト3反復連続非改善）。
- 構造：**4膜カスケード**＝2段濃縮（膜1 高透過 α42.8 → 膜2 高選択 α98.8）＋残渣の直列
  回収鎖（膜3 α56 → 膜4）＋リサイクル3本（膜2残渣→F1・膜3透過→F2・膜4透過→F1）。
  残渣 CO2 は 1.6% まで絞り切る。
- 軌跡（SHORT→cost）：0.395 → 0.391（候補棄却）→ **0.0387**（3膜化・purity 初達成）
  → 0.394（探索希釈で後退）→ 0.041（promote で復帰）→ **feasible 61.29 ★**（MEMB4 追加）
  → 62.11 → 61.95 → 62.59（3連続非改善で停止）。
- **検収 PASS**：全9反復・全アクティブ膜入口が実測 1.1000 bar（stream_results の
  pressure_bar 記録と scratch/check_blower_acceptance.py による運用検収）。

**圧力⇄段数トレードオフ（campaign 3点が完成）**：
| run | feed 圧 | 膜 | コスト |
|---|---|---|---|
| run24 | 1.0 bar（真空のみ） | 5枚 | 73.66 $/t |
| run26 | 1.1 bar（ブロワー） | 4枚 | **61.29 $/t（−17%）** |
| run25 | 1.1〜4 bar（圧縮自由） | 3枚 | 52.12 $/t（−29%） |
0.1 bar のブロワーが膜1枚と 12 $/t を代替する＝低圧側の感度が極めて急峻。

**確定知見**（詳細 run26/HANDOFF.md）：(1) 3段目は必須（ON/OFF と達成/未達が3回再現で
完全対応）。(2) 4段目が feasibility の鍵（回収 86%→90.8%・コストも改善）。(3) エージェントの
事前予測「pCO2 0.027 bar の膜4は分が悪い」は外れ——**段の追加は既存段の運転点を解放する**
（膜3が掻き出し段を降りて小型・高選択へ転身）。(4) 一度棄却された配線も下流構造が変われば
逆転する（膜3透過の行き先 V9⇄V11 が MEMB4 追加後に反転）。(5) バイナリ追加は探索を希釈する
——決着した候補を promote/削除で畳んでから足す運用が復帰の鍵（run25 と同じ教訓を独立再導出）。

**方法論上の重要発見（HANDOFF (1)）**：patience 早期終了により反復間の評価予算が
104〜284 とばらつき、**コストが評価数と完全単調相関**＝内側 BO の分散が構造の効果量を超え、
コスト軸の停止判定の信頼性を損なった。ユーザ判断（2026-07-16）：「改善がない＝嵌っている、
なら撤退」という patience の設計思想は正しいので**維持**。必要な場面では最終 best 構造のみ
大予算で仕上げ再評価する運用で対処。

**図**：`docs/run26_best_structure.{json,png}`（P&ID 規約：膜=左入・下透過(赤)・右残存(青)、
他ブロック=左入右出、直交配線のみ。各フローに圧力・CO2%・総流量、製品に純度/回収率）。

## baseline 比較・第1弾（2026-07-17）— lee3 全結合×一括 GA は feasibility とコストを両立できず

**プロトコル（ユーザ決定 2026-07-16/17）**：一括最適化側は wall-clock 基準 — 集団数を固定し
**6.5h の世代境界打ち切り**（進行中の世代は完走、`ga.max_wall_sec`、`40f216c`）。集団数は
pop 40 / 100 の2パターンで「集団数のせいでない」ことを示す。SS は 3段全結合（ss_lee3、
binary 24・連続 12・有効配線 4^6=4096）と 4段全結合（未作成）。seed は各設定 3+ を予定。

**結果（lee3 × pop 40、seed 1、いずれも ~6.5h）**：

| | SST run30 | GA penalty 法 | GA Deb 規則 |
|---|---|---|---|
| feasible 到達 | ✓ 3.3h | **✗（6.65h・3,222評価でゼロ）** | ✓ 5.1h（Gen 66） |
| purity / recovery | 95.1 / 90.2 | 85.6 / 82.8（best が infeasible） | 95.8 / 90.7 |
| best feasible コスト | **67.15 $/t** | — | **735.63 $/t（SST の 11 倍）** |
| 比エネルギー | 530 kWh/t | — | 10,226 kWh/t（19 倍） |
| 評価数 | 1,244 | 3,222 | 2,895 |

**確定知見**：
1. **penalty 法の罠が実戦で再現**：economics 由来の実効ペナルティ（~84 $/短絡単位）では
   「安い infeasible」（52.9 $/t・違反 0.166）が fitness 上勝ち、GA は feasible を出す動機を持たない。
   penalty 込み best_fitness=66.8 を「run30 に迫る」と誤読しかけた（run17 と同じ軸違い）。
2. **対策として GA 選抜を Deb の feasibility 規則に変更**（`33e24c1`、パラメータフリー、違反量は
   CBO bootstrap と同一の合計 shortfall、BAD=∞。gen_log に min_shortfall / feasible_obj_min を記録）。
   Deb 版は shortfall を単調に詰めて feasible に到達したが、**残り 1.4h でコストは 1 ドルも下がらず**
   735.63 のまま打ち切り。
3. **結論（1 seed 時点）**：同一 wall-clock の一括 GA は「feasible ゼロ（penalty）」か
   「feasible だが経済的に破綻（Deb）」の二択で、構造発見＋feasible 化＋コスト磨きを 6.1h で
   完了する SST と土俵が違う。3段全結合に feasible 配線自体は存在する（=run30 の「3段では届かない」
   は SST の候補配線内の話）ことも判明 — SST の配線候補生成の改善余地として記録。
4. **副次**：全結合トポロジーは wedge を踏みやすい（Deb 版で 33 回・99 分=予算の 25% 損失。
   run30 は 60 分）。荒い配線の Aspen 収束性が原因とみられ、比較の際は wedge 損失も併記する。

**残作業**：pop 100 × lee3、4段全結合 seed（ss_lee4.json）作成 → lee4 × pop 40/100、

   配線）で Gen 20 以降 60 世代以上 0.168 に膠着 — 3段空間（0.087）より浅い。binary 24→40 の
   探索希釈がそのまま出た。「空間を広げれば解は入るが見つからなくなる」という全結合超構造
   アプローチのジレンマの実証。一括 GA 合計 ~7,800 評価（SST の 6 倍超）・19.5h で feasible ゼロ。
4. **wedge 損失は全結合で恒常的に予算の 30%超**（129-144 分/390 分）。ランダム配線の Aspen
   収束性の悪さは全結合アプローチの隠れたコスト（SST は 60 分=16%）。

**残（matrix より）**：BO 一括（wall-clock 対応の開発から）、GA/SST の seed 追加、
GA-penalty lee4b、BO×lee4（仮・獲得関数4,096抽選）、LLM 直接解（仮）。

## baseline 比較・第3弾（2026-07-19）— 一括 BO は 4 変種すべて feasible ゼロ（失敗の階段が完成）

一括 CBO（SST の内側と同一の 2 相・同一獲得関数設定）を lee3_blower/lee4_blower に適用。
獲得関数の最適化 2 方式 × 候補生成 2 方式を検証（サンプリング方式は Morlet-Espinosa &
Flores-Tlacuahuac, AIChE J 2024 を参照実装、`2cce6ae`/`3d3512f`）。全て 6.5h バッチ境界打ち切り。

| 変種 | SS | 評価数(バッチ) | feasible | 最終 shortfall | 予算の主使途 |
|---|---|---|---|---|---|
| L-BFGS 全列挙 4096 | lee3b | 120 (5) | ✗ | 0.734 | 獲得関数 94%（~70分/バッチ） |
| L-BFGS 抽選 K=4096 | lee4b | 112 (3) | ✗ | 0.768 | 獲得関数 93%（~100分/バッチ） |
| sampling MLE 適応 | lee3b | 766 (139) | ✗ | **0.734（139バッチ不動）** | GP fit 71%（終盤14分/バッチ） |
| sampling 一様 | lee3b | 664 (101) | ✗ | 0.326 | 同上（O(n³) で自己減速） |

**確定知見**：
1. **獲得関数の最適化コストは組合せ数に比例して崩壊**（SST 内側の組合せ ≤16 → 数十秒/バッチ、
   4,096 → 70分、40 binary 空間では抽選で候補を絞っても100分）。サンプリング採点化で
   数秒/バッチに解決できるが——
2. **ボトルネックはサロゲート表現力に移るだけ**：ランダム配線の 80% が Aspen 非収束の空間では、
   GP はまず「壊れない領域」を学び浅い盆地（shortfall ~0.73）に捕まる。獲得点の BAD 率は 1% まで
   下がる（学習自体はしている）のに feasibility へ進めない。
3. **MLE 適応サンプリングはこの空間では有害**：現 best 周辺への集中が盆地脱出を阻み 139 バッチ不動。
   純一様はスパイク的に脱出して 0.326 まで降りた（それでも GA の 0.087 に遠く、feasible には未達）。
   Morlet-Espinosa の「適応サンプリング有効」という知見は、評価の大半が BAD になる強い制約付き
   実プロセス空間では逆転する——one-shot 適用の限界として記載価値あり。
4. **観測が増えると GP fit が O(n³) で自己減速**（766 点で 14 分/バッチ）。sampling BO も
   スケールしない。
5. これで**一括手法の失敗の階段が完成**：L-BFGS BO（獲得コスト死）→ sampling BO（サロゲート死）
   → GA（壁の手前 0.087）→ **SST のみ feasible 67.15 $/t**。全一括手法に SST の 2.2〜6 倍の
   評価数を与えた上での結果。

**残（matrix）**：seed 追加（SST ×4・GA ×数本）、LLM 直接解（仮）、GA-penalty lee4b、
run のアーカイブと図の実データ化。

4. **binary 膨張が探索を薄める**（iter_005/006、run32 と同一の失敗を独立再現）。6 binary 時に

**ユーザ決定（2026-07-28、run33 完了後）**：
- **run32 は Opus 5 実行のためモデル汚染とみなし、論文1の SST 標本分布から除外**。

## run34（2026-07-28〜29）— v1 seed 4本目（Opus 4.8）・feasible 未達のまま正規収束停止（recovery 87% 天井と誤結論）

**結果**：**feasible 未達**。best（shortfall 基準）= iter_005：purity 95.7% / **recovery 87.0%** /

87% 天井を破れず → 収束停止。

**HANDOFF の結論「ブロワー限定の熱力学的天井 ~0.87」は誤り**（run30/32/33 が同一 campaign で

run32 HANDOFF が警告した「**構造が物理でなく最適化器の疲弊で棄却される**」がそのまま run を
殺した形 — MEMB5 は refuted ではなく never-engaged だった。ブラインド原則ゆえ run34 は他 run の

**確定知見**：

1. **SST の成功率は 100% ではない**。有効標本 3 本中 feasible 到達 2（run30 67.15 / run33 66.44）、

   феasible を取った。**「gated 追加は binary を整理してから、拡張直後の反復の棄却は信用しない」**が
   3 run 分の証拠で確立。
3. **3膜構成の recovery 85.5% 天井は 4 run 連続で数値まで再現**（85.4 / 85.5 / 85.5 / 85.5）。

4. HANDOFF の副次的指摘「gated 追加で COMP を挟めない tooling gap」は**誤認**（run32 が
   gated COMP＋下流固定膜の形で実際に実行済み。v1 指示書にも記載あり）。ツール変更は不要。

**T_max への影響**：run34 は 7.8h。有効標本の最長は依然 run33 の ~9.0h。

## baseline 10h campaign（2026-07-29〜08-07）— T_max=10h・正しい独立 seed で全 20 run が feasible ゼロ

**プロトコル**：T_max=10h 方式（2026-07-29 決定）。wall-clock 10h 打ち切り（GA=世代境界、
BO=バッチ境界）、`--seed` 修正（`3fe69e6`）後の正しい独立 seed 1〜4。
GA-Deb: lee3/lee4_blower × pop40/100 × 4 seed = 16 run、2相 CBO: lee3_blower × 4 seed = 4 run。
driver は `scratch/baseline_campaign_10h.py`（逐次・再開対応・即死ガード付き）。

**結果：20 run・総 47,784 評価・約 210h で feasible 解ゼロ。**

| 手法 | run 数 | 総評価 | feasible | 最接近 min_shortfall |
|---|---|---|---|---|
| GA-Deb lee3（pop40/100 ×4seed） | 8 | 27,322 | 0 | 0.0147（pop40 seed3） |
| GA-Deb lee4（pop40/100 ×4seed） | 8 | 19,962 | 0 | 0.0163（pop40 seed1） |
| 2相 CBO lee3（×4seed） | 4 | 500 | 0 | 0.36〜0.73 |

**確定知見**：

1. **一括最適化は 10h・数千評価でも feasible 領域に到達できない**（20/20 全滅）。GA は shortfall
   0.015〜0.21 で停滞、CBO は獲得関数律速で 10h あたり ~120 評価しか回らず 0.36 以上と遠い。
   SST（4 run 中 3 feasible、66.44〜67.67 $/t、3.7〜7.7h）との対比が完全確定。
2. **旧 6.5h 時代の GA-Deb feasible（735.63 $/t）は seed バグ下の偶然**で、正しい独立 seed では
   4 seed × 2 SS × 2 pop の 16 通りで一度も再現しなかった。
3. **旧「×3 seed」データは独立標本ではなかった**（--seed が run 名にしか効かず、GA 初期集団が
   全 seed で同一 = gen1 best 295.354 を共有。分岐は Aspen 評価ノイズのみ）。10h campaign で全て
   置換済み。旧 6.5h run は `_65h` サフィックスで保全（補助表用）。
4. **運用記録**：Aspen プロセス漏れは run あたり +0〜6 個で蓄積（メモリ影響は軽微、~380MB/個）。
   ゾンビ ~17 個超で CBO の初回評価開始が最大 ~50 分遅延する実害を確認 → 環境公平性のため
   **CBO seed2 はクリーン環境で再走して差し替え**（劣化版は `_degraded` として保全）、seed4 も
   クリーン実施。再起動時に旧 driver がログオフ中の残りキューを即死消化する事故が1回
   （データ損失なし・復旧済み・driver に即死ガード追加）。
5. CBO の獲得関数は1バッチ 1〜3h（24 binary の one-hot 空間で L-BFGS）。wall-clock 打ち切りは
   バッチ境界のため実終了は 10.4〜11.6h（超過は獲得関数中の空走で結果に影響なし）。

**論文1の比較データはこれで完備**：SST n=4（成功3・未達1）+ baseline n=20（全滅）+
run32（モデル頑健性の傍証）+ 旧 6.5h 群（補助）。

**seed 運の検証について（2026-08-07 ユーザ決定）**：仕上げ再評価（新規 seed での best 構造検算）は
**実施しない**。run33/35 終盤の同一構造再実行（各 4 標本、feasibility 維持・コスト帯 66〜76 $/t）が
既存データとして同じ役割を果たすため。必要になればプロトコル不変で後日追加可能。
